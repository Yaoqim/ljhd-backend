# LJHD 后端项目核心开发规则（强制执行）

## 项目基本信息

- **项目名称**: 连接互动统一认证微服务系统
- **技术栈**: Java 8 + Spring Cloud 2021.0.7 + Spring Boot 2.7.10 + MyBatis-Plus + Nacos
- **构建工具**: Maven 3.6+
- **数据库**: MySQL 8.0

---

## 第一部分：代码分层规范

### 1. URL 路由深度规范

- **非 ID 查询**: 最多 3 层 — 示例：`/system/user/list`
- **RESTful 带 ID**: 最多 4 层 — 示例：`/system/user/{id}`
- **禁止**: 深度超过 4 层的路由

### 2. Controller 层职责（仅做两件事）

#### 2.1 允许的操作

- ✅ **权限校验** - 使用权限框架验证用户权限
- ✅ **参数校验** - 使用 @Valid 注解进行输入参数校验
- ✅ **HTTP 协议处理** - 接收请求、调用 Service、返回响应

#### 2.2 禁止的操作

- ❌ **业务逻辑实现** - 不在 Controller 中写业务处理代码
- ❌ **事务管理** - @Transactional 只能在 Service 中使用
- ❌ **数据库操作** - 不能直接调用 Mapper，必须通过 Service
- ❌ **复杂计算** - 所有业务计算放在 Service 中

### 3. Service 层职责（业务引擎）

#### 3.1 必须实现

- ✅ **所有业务逻辑** - 增删改查的核心业务
- ✅ **事务管理** - 所有修改操作必须加 @Transactional(rollbackFor = Exception.class)
- ✅ **多步骤业务流程** - 复杂业务的步骤编排和失败处理
- ✅ **跨表业务协调** - 涉及多个 Entity 的操作

#### 3.2 Service 接口规范

- **必须存在**: 每个 Entity 必须有 Service 接口和 ServiceImpl 实现类
- **不能省略**: 即使只有 CRUD 操作也需要 Service 接口
- **一对一原则**: 一个 Entity 对应一个 Service

### 4. Mapper 层规范

#### 4.1 Mapper.java 接口

- ✅ **仅定义方法签名** - 接口只声明方法，不实现
- ❌ **禁止写 SQL** - @Select、@Insert 等注解 SQL 在复杂查询中禁止使用

#### 4.2 Mapper.xml 文件

- ✅ **所有 SQL 语句都在这里** - 包括简单查询、复杂 JOIN、动态 SQL
- ✅ **多表联合查询在这里实现** - 所有 JOIN 操作必须在 XML 中完成

## 第二部分：实体与数据对象规范

### 1. Entity 实体类规范

#### 1.1 属性要求

- ✅ **仅包含数据库字段** - 与数据表字段一一对应
- ✅ **可选：关联关系属性** - 有特殊业务需求时可添加（需注解为 @Transient）
- ❌ **禁止业务属性** - 不包含计算字段、临时字段、非数据库字段

#### 1.2 字段说明

```java
@Entity
@Table(name = "user")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "user_name")
    private String userName;  // ✅ 直接对应数据库字段

    @Column(name = "create_time")
    private LocalDateTime createTime;  // ✅ 从服务器自动获取

    @Transient
    private String departmentName;  // ⚠️ 关联字段（如果需要），必须加 @Transient

    // ❌ 不允许这样的字段：
    // private String tempField;
    // private Integer calculatedValue;
}
```

### 2. DTO 数据传输对象规范

#### 2.1 DTO 类型与用途

- **SearchDto** - 用于多参数查询条件，后缀统一为 `SearchDto`
- **Dto** - 用于新增/修改操作，后缀为 `Dto`

#### 2.2 DTO 数量限制

- **每个 Controller 最多 2 个 DTO**：
  - 1 个 SearchDto（查询条件）
  - 1 个 Dto（增删改参数）

#### 2.3 参数校验规范

- ✅ **在 Dto 中配置** - 使用 @NotNull、@NotBlank、@Length 等注解
- ❌ **不在 SearchDto 中配置** - 查询条件可为空，不需要校验
- ❌ **禁止校验非必传参数** - 如果某个参数是可选的，不加校验注解
- 在 Controller 中使用 @Valid 注解自动触发 Dto 的参数校验

#### 2.4 示例

```java
// ✅ 正确
@Data
public class UserSearchDto {
    private String userName;           // 不加校验，可选
    private LocalDateTime startDate;   // 可选
}

@Data
public class UserDto {
    @NotBlank(message = "用户名不能为空")
    private String userName;           // 必填

    @NotNull(message = "邮箱不能为空")
    @Email
    private String email;              // 必填

    // private Integer userId;  ❌ 不应该在这里，从登录信息获取
    // private LocalDateTime createTime;  ❌ 不应该在这里，从服务器获取
}
```

### 3. VO 视图对象规范

#### 3.1 VO 类继承要求

- ✅ **必须继承对应的 Entity** - VO extends Entity
- ✅ **用于响应数据** - 返回给前端的数据用 VO 包装

#### 3.2 VO 与 Entity 的区别

- **VO** = Entity + 前端所需的额外字段
- VO 中可以加入关联表的数据、计算字段等

#### 3.3 多表查询返回 VO

- ✅ 在 Mapper.xml 中定义多表 JOIN 查询，返回结果映射到 VO
- ❌ 禁止在 Java 代码中多次查询后手动组装数据

```java
// ✅ 正确的 VO
@Data
@EqualsAndHashCode(callSuper = true)
public class UserVO extends User {
    private String departmentName;      // 关联部门名称
    private String roleNames;           // 关联角色
}

// ❌ 不正确
public class UserVO {  // 不继承 User
    private Long id;
    private String userName;
}
```

## 第三部分：接口命名规范（强制执行）

所有 RESTful 接口必须遵循以下命名标准：

| 操作 | 查询类型   | 接口路径 | HTTP 方法 | 请求体            | 说明                   |
| ---- | ---------- | -------- | --------- | ----------------- | ---------------------- |
| 查询 | 不分页列表 | /list    | GET       | 无                | 查询全部数据，无分页   |
| 查询 | 分页列表   | /page    | POST      | SearchDto         | 分页查询，必须 POST    |
| 查询 | 单条记录   | /{id}    | GET       | 无                | 根据 ID 查询单条       |
| 新增 | -          | /add     | POST      | Dto               | 添加单条记录           |
| 修改 | -          | /update  | POST      | Dto(含 id)        | 修改单条记录           |
| 修改 | -          | /edit    | POST      | Dto(含 id)        | 同 /update，可选       |
| 删除 | 单条       | /{id}    | POST      | 无                | 根据 ID 删除（POST）   |
| 删除 | 批量       | /delete  | POST      | List<Long> 或 IDs | 批量删除               |
| 其他 | -          | /自定义  | -         | -                 | 业务相关操作按业务命名 |

### 2. Mapper 实现规范

#### 2.1 简单查询

```java
// UserMapper.java
public interface UserMapper extends BaseMapper<User> {
    // 继承 BaseMapper 已有 CRUD 基础方法
    // 自定义复杂查询通过 XML 实现

```

#### 2.2 多表联合查询（必须用 XML）

**❌ 禁止的实现方式**：

```java
// Service 中的错误实现 - N+1 问题
@Override
public List<UserVO> getUsersWithDepartment() {
    List<User> users = userMapper.selectList(null);  // 查询 1 次
    for (User user : users) {
        Department dept = departmentMapper.selectById(user.getDeptId());  // N 次查询
        // 手动组装...
    }
}
```

**✅ 正确的实现方式**：

```xml
<!-- UserMapper.xml -->
<select id="selectUserWithDepartment" resultType="com.ljhd.system.db.vo.UserVO">
    SELECT
        u.id,
        u.user_name,
        u.email,
        d.id as departmentId,
        d.department_name
    FROM user u
    LEFT JOIN department d ON u.dept_id = d.id
    WHERE u.is_deleted = 0
    ORDER BY u.id
</select>
```

```java
// UserMapper.java
public interface UserMapper extends BaseMapper<User> {
    List<UserVO> selectUserWithDepartment();
}
```

#### 2.3 动态查询 SQL

```xml
<!-- UserMapper.xml - 分页查询示例 -->
<select id="selectByCondition" parameterType="com.ljhd.system.db.dto.UserSearchDto"
        resultType="com.ljhd.system.db.vo.UserVO">
    SELECT
        u.id,
        u.user_name,
        u.email,
        d.department_name
    FROM user u
    LEFT JOIN department d ON u.dept_id = d.id
    WHERE u.is_deleted = 0
    <if test="userName != null and userName != ''">
        AND u.user_name LIKE CONCAT('%', #{userName}, '%')
    </if>
    <if test="startDate != null">
        AND u.create_time &gt;= #{startDate}
    </if>
    <if test="endDate != null">
        AND u.create_time &lt;= #{endDate}
    </if>
    ORDER BY u.id DESC
</select>
```

### 3. Mapper.java 注解 SQL 的使用原则

- ✅ **简单查询可用注解** - 单表、简单 WHERE 条件可使用 @Select
- ❌ **复杂查询禁止注解** - 多表 JOIN、子查询、动态 SQL 必须用 XML
- **建议**: 为保证代码一致性，所有 SQL 都在 XML 中编写

## 第六部分：事务管理规范

### 1. @Transactional 使用原则

#### 1.1 在 Service 层使用

```java
@Service
public class UserServiceImpl implements UserService {

    // ✅ 正确：Service 方法使用 @Transactional
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void createUser(UserDto userDto) {
        // 业务逻辑
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void updateUser(UserDto userDto) {
        // 业务逻辑
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void deleteUser(Long userId) {
        // 业务逻辑
    }

    // ✅ 查询方法可以不用 @Transactional
    @Override
    public UserVO getUserById(Long userId) {
        return userMapper.selectById(userId);
    }
}
```

#### 1.2 禁止在 Controller 中使用

```java
// ❌ 错误：不在 Controller 中使用 @Transactional
@RestController
@RequestMapping("/system/user")
public class UserController {

    @Transactional  // ❌ 这是错误的
    @PostMapping("/add")
    public BaseResult<Void> add(@Valid @RequestBody UserDto userDto) {
        userService.createUser(userDto);
        return BaseResult.succeed();
    }
}
```

### 2. 多步骤业务的事务管理

```java
@Service
public class OrderServiceImpl implements OrderService {

    @Autowired
    private OrderMapper orderMapper;

    @Autowired
    private OrderItemMapper orderItemMapper;

    @Autowired
    private GoodsMapper goodsMapper;

    // ✅ 整个流程在一个事务中
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void createOrder(OrderDto orderDto) {
        // 步骤 1：创建订单
        Order order = new Order();
        order.setOrderNo(generateOrderNo());
        order.setTotalAmount(orderDto.getTotalAmount());
        orderMapper.insert(order);

        // 步骤 2：添加订单项目
        for (OrderItemDto itemDto : orderDto.getItems()) {
            OrderItem item = new OrderItem();
            item.setOrderId(order.getId());
            item.setGoodsId(itemDto.getGoodsId());
            item.setQuantity(itemDto.getQuantity());
            orderItemMapper.insert(item);

            // 步骤 3：更新商品库存
            Goods goods = goodsMapper.selectById(itemDto.getGoodsId());
            goods.setStock(goods.getStock() - itemDto.getQuantity());
            goodsMapper.updateById(goods);
        }

        // 如果任何一步失败，整个事务会回滚，包括库存更新
    }
}
```

## 第八部分：最佳实践检查清单

### 创建新功能时的检查清单

- [ ] **Entity** - 仅包含数据库字段，无业务属性
- [ ] **Mapper** - 有对应的 Mapper.java 和 Mapper.xml
- [ ] **Service** - 有接口和实现类，实现业务逻辑
- [ ] **Controller** - 仅做参数校验和调用 Service，不含业务逻辑
- [ ] **DTO** - 最多 2 个（SearchDto 和 Dto），参数校验在 Dto 中
- [ ] **VO** - 继承对应 Entity，用于响应
- [ ] **多表查询** - 用 Mapper.xml JOIN 实现，返回 VO
- [ ] **事务管理** - @Transactional 仅在 Service 实现类上
- [ ] **用户信息** - 从 CurrentUserUtil 获取，不在 DTO 中
- [ ] **时间字段** - 使用 LocalDateTime.now()，不前端传入
- [ ] **接口命名** - 遵循 /list、/page、/add、/update、/{id}、/delete

## 第五部分：新增用户逻辑实现指南（Service 层）

### 核心原则

**新增用户的业务逻辑必须在 Service 层实现，不记在 Controller 层**

- ✅ `UserService.createUser()` - 管理员手动新增
- ✅ `UserService.registerUserByWechat()` - 微信登录注册
- ✅ `UserService.registerUserByPhone()` - 验证码登录注册

### 场景对比

| 场景 | 调用方式 | 事务 | 密码 | userCode 生成 |
|------|---------|------|------|---------------|
| 管理员创建 | Controller 调用 | ✅ @Transactional | 临时密码 | 管理员输入 |
| 微信登录 | AuthController 调用 | ✅ @Transactional | 无 | 自动生成 |
| 验证码登录 | AuthController 调用 | ✅ @Transactional | 无 | 自动生成 |

### 实现样板

#### 1. 管理员创建用户

```java
@Service
public class UserServiceImpl implements UserService {

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void createUser(UserDto userDto) {
        // ✅ 获取当前管理员
        LoginAppUser currentUser = CurrentUserUtil.getCurrentLoginUser();

        // 1. 检查 userCode 甯一性
        if (userMapper.selectByUserCode(userDto.getUserCode()) != null) {
            throw new IllegalArgumentException("用户编码已存在");
        }

        // 2. 创建 User
        User user = new User();
        user.setUserCode(userDto.getUserCode());
        user.setNickname(userDto.getNickname());
        user.setPhone(userDto.getPhone());
        user.setCreateUserId(currentUser.getUserId());
        user.setCreateBy(currentUser.getUserName());
        user.setCreateTime(LocalDateTime.now());
        user.setPassword(generateTemporaryPassword());
        user.setStatus("ENABLED");
        userMapper.insert(user);

        // 3. 创建算力账户、绑定记录
        AIAccount aiAccount = new AIAccount();
        aiAccount.setUserId(user.getId());
        aiAccount.setUserCode(user.getUserCode());
        aiAccount.setBalance(0L);
        aiAccount.setCreateTime(LocalDateTime.now());
        aiAccountMapper.insert(aiAccount);

        if (userDto.getPhone() != null) {
            ThirdPartyLoginBinding binding = new ThirdPartyLoginBinding();
            binding.setUserCode(user.getUserCode());
            binding.setLoginType("MOBILE_CODE");
            binding.setThirdPartyUid(userDto.getPhone());
            binding.setBoundTime(LocalDateTime.now());
            binding.setStatus("ACTIVE");
            bindingMapper.insert(binding);
        }
    }
}
```

```java
@Override
@Transactional(rollbackFor = Exception.class)
public LoginResponse registerUserByWechat(String code, String appCode) {
    String unionId = getWechatUnionId(code);

    ThirdPartyLoginBinding binding = bindingMapper
        .selectByThirdPartyUid(unionId, "WECHAT");

    if (binding != null) {
        bindingMapper.updateLastLoginTime(binding.getUserCode(), LocalDateTime.now());
        return buildLoginResponse(binding.getUserCode(), appCode);
    }

    // 自划养注册：一次性创建 User/AIAccount/UserApplication/UserRole/ThirdPartyLoginBinding
    String userCode = "wechat_" + System.currentTimeMillis() + "_"
        + RandomStringUtils.randomAlphanumeric(6);

    WechatUserInfo wechatUser = getWechatUserInfo(code);
    User user = new User();
    user.setUserCode(userCode);
    user.setNickname(wechatUser.getNickname());
    user.setCreateTime(LocalDateTime.now());
    user.setStatus("ENABLED");
    userMapper.insert(user);

    // ✅ 一个事务中同时创建相关数据
    AIAccount aiAccount = new AIAccount();
    aiAccount.setUserId(user.getId());
    aiAccount.setUserCode(userCode);
    aiAccount.setBalance(0L);
    aiAccount.setCreateTime(LocalDateTime.now());
    aiAccountMapper.insert(aiAccount);

    UserApplication userApp = new UserApplication();
    userApp.setUserCode(userCode);
    userApp.setAppCode(appCode);
    userApp.setCreateTime(LocalDateTime.now());
    userApplicationMapper.insert(userApp);

    UserRole userRole = new UserRole();
    userRole.setUserCode(userCode);
    userRole.setRoleCode(getAppDefaultRole(appCode));
    userRole.setCreateTime(LocalDateTime.now());
    userRoleMapper.insert(userRole);

    ThirdPartyLoginBinding newBinding = new ThirdPartyLoginBinding();
    newBinding.setUserCode(userCode);
    newBinding.setLoginType("WECHAT");
    newBinding.setThirdPartyUid(unionId);
    newBinding.setNickname(wechatUser.getNickname());
    newBinding.setBoundTime(LocalDateTime.now());
    newBinding.setLastLoginTime(LocalDateTime.now());
    newBinding.setStatus("ACTIVE");
    bindingMapper.insert(newBinding);

    return buildLoginResponse(userCode, appCode);
}
```

### 实现注意的事项

✅ **必须使用 @Transactional** - 业务完整性幼程
✅ **一次性创建相关表** - User/AIAccount/UserApplication/UserRole/ThirdPartyLoginBinding
✅ **重复登录只更新时间** - 不重复创建
✅ **不可在 Controller 中变更** - 业务逻辑待在 Service
